August 2026 · PRIVI research

Before an AI can change anything

Drafting a refund and sending the money need different permissions. That difference should be explicit before an AI gets access.

When this was measured
Session 4 corpus measurement, frozen aggregate computed 6 August 2026 at 20:13 EDT (7 August, 00:13 UTC). This is an aggregate timestamp, not a new scan.
Historical result, not current accuracy. Note written 1 November 2026; explanation revised 3 November 2026.

Imagine a customer service agent with a tool called “handle refund.” Does that tool look up a purchase, draft a recommendation, or send money back? Before giving it access, the team needs to know. The answer changes which account it should use, when a person must approve an action, and what the system must prevent. This example illustrates the decision; it is not an incident found in the research.

That is why I looked at tool descriptions in PRIVI. The historical sample contained 4,445 observed tools across 199 assessed public repositories. Only 103, or 2.3%, stated whether they changed anything. The selection frame had 200 repositories; one failed to scan. The result exposed a missing starting point for review. It did not show that the remaining tools were dangerous or acting without permission.

My practical takeaway is to write down the allowed action before checking it. For the refund example: may the agent only draft, or also pay? Which amounts require a person? What happens if approval is missing? Put the answers in one reviewable record, then enforce the limits through the system's permissions. Describing a restriction does not make it hold.

Next, test an allowed action and an action that should be blocked in a controlled environment. Keep the request, the approval, the attempted action and the result. Those are proposed steps for applying the lesson. This study did not run the sampled tools or establish whether their live controls worked.

The distinction matters because a reassuring number can hide unanswered questions. Among 100 tools with readable implementations and checkable claims, the analysis found zero contradictions. The detector was deliberately narrow: it did not follow calls into helper functions, and it did not treat every HTTP POST as a write. That zero cannot establish that the tools were safe.

The repositories were selected before measurement and fetched at pinned commits. This was static analysis of that sample, frozen in August 2026. It was not a measurement of every agent or of today's systems.

I retired PRIVI as a product. What I keep is a way to make a review useful: define what is allowed, check whether the boundary holds, and name what remains unknown. A finding earns its place when it changes a decision. Here, that decision is what access to grant and what evidence to require before granting it.
